# Prompt Pad · 案例调研与技术选型

> 调研日期：2026-10-14 ｜ 目标平台：Windows（后续可扩 macOS）
> 一句话目标：做一个常驻系统最上层、全局热键唤起、带私人记忆的提示词优化 Pad。

---

## 一、直接对标：腾讯 WorkBuddy

WorkBuddy 是腾讯的企业级 AI 助手，**你要做的 Pad 本质上是它的「增强提示词」按钮 + 「记忆」库 + 常驻浮窗形态**三者的合体。它已经验证了这条产品路径。

### 1.1 三个可借鉴的核心机制

| 机制 | WorkBuddy 做法 | 对我们的启示 |
|------|---------------|-------------|
| **增强提示词** | 输入框右下角闪光图标，点一下把原始诉求改写得更干净、更聚焦、更少废话 | 核心交互就应该是**一键改写**，而不是让用户面对一个复杂的编辑器 |
| **记忆（自动）** | 每晚自动从当天对话历史中提取有价值信息进个人记忆库，如「用户熟悉上下文工程」，**用户零操作** | 记忆必须是**自动沉淀**的。让用户手动维护 memory.md 一定坚持不下来 |
| **个性化（手动）** | 用户主动设置的称呼、语气、人设、回复风格 | **自动记忆与手动偏好必须是两个独立存储**，WorkBuddy 明确把两者二分 |

> 这条二分法很重要：**自动沉淀的**需要日志归因和错误清理，**手动声明的**需要版本控制和回滚。混在一起会导致记忆库被污染后无法回溯。

### 1.2 记忆迁移机制（值得直接抄）

WorkBuddy 支持从其他 AI 产品迁移记忆：让原来的 AI 生成一份「关于你的记忆总结」，用户检查无误后导入。

这解决了冷启动问题——**新装的 Pad 记忆库是空的，必须有一条快速灌入既有偏好的路径**。我们的 `memory.md` 应该支持同样的导入格式。

### 1.3 反面教训：上下文预算管理

WorkBuddy 官方技巧文档反复强调同一件事：**别让技能定义、废话提示词吃掉上下文窗口**。其建议是「模型上下文用量占一半就该压缩或开新会话」。

这直接约束我们的设计：**Pad 注入的记忆必须是精选子集，不是整个 memory.md**。这一点在《02-私人记忆库设计》里展开。

📎 来源：https://joto.ai/blog/news-64f7ab6dd1175c8b77

## 二、常驻置顶 Pad 的同类实现

### 2.1 WinDOT —— 最贴近的架构参考

WinDOT 是一个「悬浮小圆点 → 点击展开工具面板」的 Windows 应用，其规格书几乎是本项目的现成需求文档：

- **形态**：一个 40-56px 的小 DOT 常驻桌面，点击展开为面板，点击外部收起
- **核心原则**：*TINY WHEN UNUSED → POWERFUL WHEN OPENED*（不用时极小，打开时强大）
- **技术栈**：Tauri 2 + React + TypeScript + Vite + Tailwind + Rust，并明确写了「**除非某个 Windows 能力绝对必需，否则不要用 Electron**」
- **交互细节**：无边框透明窗口、拖拽、位置持久化、多显示器、尊重 DPI、点击外部检测、Esc 关闭、Ctrl+Space 全局热键、开机自启、150-250ms 动画

### 2.2 TimeFence —— 「置顶但不抢焦点」

一个常驻置顶的倒计时 HUD，卖点是 **always-on-top 且不抢键盘焦点**，让你能继续在真正的编辑器里打字。同时强调 **local-first、无遥测、无 Electron 税**。

> 这条对我们的 Pad 同样关键：**用户点了 Pad 之后，焦点必须能还给原来的应用**。否则 Pad 就变成了一个打断工作流的怪物。

### 2.3 其他可参考

- **Handbook**：一组小尺寸、可移动、可隐藏的窗口，强调「不占屏幕」
- **Pinny Notes**：右键即可置顶的便签，最小化的 pin 交互
- **Claude Code Windows HUD**：Electron 实现的多模态桌面叠加层（屏幕视觉 + 麦克风 + 系统音频 + 全局按键映射），证明 Electron 也能做，但更重

### 2.4 Tauri 的已知坑

Tauri 官方 issue #116 讨论了「alwaysOnTop 时点击任务栏图标不应最小化」：Windows 和 macOS 可实现，**Linux 基本无解**。社区反馈 `skipTaskbar: true` 配合移除标题栏最小化按钮可以解决大部分场景。

📎 来源：https://pastebin.com/xVX9EsG6 ｜ https://automatalabs.ca/best-always-on-top-countdown-widget ｜ https://github.com/tauri-apps/tao/pull/116

## 三、技术栈选型

### 3.1 结论：Tauri 2 + React + TypeScript + Rust

| 层 | 选型 | 理由 |
|----|------|------|
| **外壳** | Tauri 2 | 安装包小、内存占用低、透明置顶窗口支持完善、原生托盘与全局热键插件齐备。WinDOT 与 TimeFence 两个同类产品都选它并公开以「无 Electron 税」为卖点 |
| **界面** | React + TypeScript + Vite + Tailwind | 生态成熟，组件化好做，Pad UI 迭代快 |
| **后端** | Rust | 负责窗口控制、SQLite、embedding 推理、文件系统监听 |
| **存储** | SQLite + FTS5 + sqlite-vec | 单文件、零运维、全文与向量双路检索（详见《02-私人记忆库设计》） |
| **嵌入模型** | ONNX 本地推理（bge-m3 或 multilingual-e5-small） | 完全离线，数据不出本机 |
| **大模型** | MiniMax API / OpenAI 兼容端点 / Ollama 三选一可配 | 支持本地模型以满足隐私要求 |

### 3.2 为什么不是 Electron

Electron 能做且生态更全（`BrowserWindow` 的 `transparent` / `alwaysOnTop` / `frame:false` / `skipTaskbar` / `setIgnoreMouseEvents` 一应俱全），但常驻应用的内存占用是硬伤——**一个 Pad 常驻后台却吃掉上百 MB RAM，说不过去**。

如果你需要深度依赖 Node 生态的现成库、或团队只有前端背景、且不在意内存，可以选 Electron 作为降级方案。功能上没有做不到的事。

### 3.3 为什么不是 PyQt/PySide

Python 生态做本地 embedding 和 SQLite 很舒服（`sqlite-vec` 直接 `pip install`），但透明无边框窗口的精细控制、多显示器 DPI 处理、打包体积都逊于 Tauri。除非你其余工具链全在 Python，否则不建议。

### 3.4 关键实现要点

**窗口配置（tauri.conf.json）**

```jsonc
{
  "label": "pad",
  "transparent": true,     // 透明背景
  "decorations": false,    // 无系统边框
  "alwaysOnTop": true,     // 常驻最上层
  "skipTaskbar": true,     // 不占任务栏，避免被误最小化
  "resizable": false,
  "shadow": false,         // 透明窗口在 Windows 下不自动带阴影，需自绘
  "focus": false           // 启动时不抢焦点
}
```

**需要的 Tauri 插件**

| 插件 | 用途 |
|------|------|
| `tauri-plugin-global-shortcut` | Ctrl+Space 全局唤起/收起 |
| `tauri-plugin-single-instance` | 单实例，第二次启动唤醒已有实例 |
| `tauri-plugin-tray-icon` | 托盘菜单（显示/隐藏/退出/设置） |
| `tauri-plugin-autostart` | 开机自启 |
| `tauri-plugin-clipboard-manager` | 读写剪贴板 |

**五个必须处理的 Windows 细节**

1. **点击穿透**：收起态要「透明区域不拦截鼠标」，用 `set_ignore_cursor_events(true)`，但这样就收不到 hover——需要在展开态及时关掉、收起态开启。
2. **不抢焦点**：置顶但 `set_focusable(false)`，让用户点完 Pad 能直接回到原窗口继续打字。
3. **多显示器 + DPI**：用 `available_monitors()` / `current_monitor()` / `scale_factor()`，**持久化的是「哪块屏 + 屏内百分比坐标」而不是绝对像素**，否则换分辨率或拔掉扩展屏就会飘到屏幕外。
4. **屏幕边缘展开**：展开面板时自动判断方向（靠上则向下、靠右则向左），**面板绝不允许出屏**。
5. **全屏游戏/视频**：普通 always-on-top 在独占全屏下会失效，需要置 `WS_EX_TOPMOST` 并在检测到全屏时临时隐藏。

## 四、实施路线建议

按这个顺序做，每一步都能独立验证：

1. Tauri 2 + React 骨架 + 透明无边框窗口
2. 常驻 DOT：拖拽、置顶、不抢焦点、位置持久化
3. 展开/收起动画 + 边缘自适应
4. 最小可用输入框 + 调用模型做提示词改写（先不做记忆）
5. 接 SQLite 落库，开始记录 `PE-XXXX-XXX`
6. 加全局热键 + 托盘 + 开机自启
7. 接入检索层（先纯 FTS5，确认有需要再加向量）
8. 加自动记忆沉淀（夜间任务，把高频有效手法晋升为记忆条目）

> **第 4 步是产品的真正价值所在，第 7-8 步才是「越用越聪明」。** 不要在检索层上过早投入——先积累够 20-30 条真实记录，才知道检索到底需要模糊匹配还是精确匹配。
