- 项目背景与交付目标：Prompt Pad 是常驻 Windows 系统最上层、全局热键（Ctrl+Space）唤起、带私人记忆的提示词优化 Pad。按 8 步实施路线交付，每步独立可验证：①Tauri 2 + React 骨架 + 透明无边框窗口 ②常驻 DOT（拖拽/置顶/不抢焦点/位置持久化）③展开收起动画 150-250ms + 边缘自适应 ④最小输入框 + 模型改写（先无记忆）⑤SQLite 落库记录 PE-YYYY-NNN ⑥全局热键 + 托盘 + 开机自启 ⑦检索层（先纯 FTS5，确认需要再向量）⑧自动记忆沉淀夜间任务
- 已知风险线索：①Tauri 透明置顶窗口在 Windows 的已知坑（官方 issue #116：alwaysOnTop 时点击任务栏图标不应最小化；skipTaskbar:true 配合移除标题栏最小化按钮可缓解大部分场景；Linux 基本无解，本期不做 Linux）②普通 always-on-top 在独占全屏（游戏/视频）下失效，需置 WS_EX_TOPMOST 并在检测到全屏时临时隐藏 ③多显示器 + DPI 下位置漂移（必须持久化「哪块屏 + 屏内百分比坐标」而非绝对像素）④sqlite-vec / ONNX 在 CPU 上的性能（bge-m3 延迟 0.2-0.5s，e5-small 更轻但中文检索质量待实测）⑤自动记忆沉淀的污染风险（垃圾自动进、垃圾自动扩散），已设计四道防线：人工裁决闸门 / 候选不注入（验证 2 次才升 active）/ memory.md 纯 Markdown 全量可读 / memory/ 目录纳入 git 每日提交 ⑥模型 API 费用与 API key 泄漏 ⑦记忆库冷启动（已设计三条填充路径：批量回填、AI 迁移导入 preference 类记忆、前 10 次使用豁免权重惩罚）
- 不可妥协约束：置顶但不抢焦点（set_focusable(false)）；数据不出本机（嵌入必须本地 ONNX 推理）；memory.md 纯 Markdown 全量可读且 memory/ 目录纳入 git 每日提交；单次注入记忆总量 ≤800 token；禁止 Electron 除非某个 Windows 能力绝对必需；版本控制用 git
- 团队与时间资源：1 名个人开发者 + AI 编码 agent 协作；成本 = API 调用费 + 本地算力；无专职 QA / 运维

## 任务
1. 从输入线索出发扩展出至少 8 条风险，覆盖技术、进度、依赖、合规、运维 5 类。
2. 为每条风险填表：编号、风险描述、类别、概率、影响、等级、触发信号、缓解措施、责任人、兜底方案。
   - 概率与影响只用 高/中/低，等级由两者推导。
   - 触发信号写成可观测事件或阈值，例如「P95 延迟 > 500ms 且持续 10 分钟」。
   - 缓解措施必须是具体动作，不是「加强沟通」这类空话。
3. 对高等级风险（高×高、高×中）各给 1 条 48 小时内可执行的动作，写明执行角色与产出物。
4. 汇总需要向上反馈或需要外部确认的事项。
